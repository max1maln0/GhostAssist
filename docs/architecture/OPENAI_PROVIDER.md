# Stage 4.2 — OpenAI Provider

OpenAI подключён к реальному Provider Registry. Генерация использует официальный
Python SDK и Responses API, транскрибация — Audio Transcriptions API для готовых
WAV-сегментов. Realtime, Claude, Ollama и custom endpoints не добавлены.
В Stage 4.2.1 добавлен [Dashboard 2.0](DASHBOARD_2.md): независимые селекторы генерации/транскрибации и безопасные поля ключей.

## Настройка

Установите обновлённые зависимости: `python -m pip install -r requirements.txt`.
Остановите службу и Dashboard, отредактируйте .env, затем заново запустите Dashboard
и службу. Не храните ключ в Markdown-профиле и не публикуйте файл конфигурации.

Полностью OpenAI:

```dotenv
SCHEMA_VERSION=2
OPENAI_API_KEY=<ваш ключ, только в локальном .env>
GENERATION_PROVIDER=openai
GENERATION_MODEL=gpt-5.6-terra
TRANSCRIPTION_PROVIDER=openai
TRANSCRIPTION_MODEL=gpt-transcribe
```

Для этой конфигурации GEMINI_API_KEY не нужен. Пример ключа в угловых скобках нужно
заменить собственным значением. Dashboard редактирует оба ключа и четыре поля привязок; сохранённые секреты не подставляются обратно в поля. При отсутствии ключа выбранного
провайдера запуск службы блокируется с именем нужного параметра, без значения секрета.

Смешанная конфигурация с транскрибацией OpenAI и генерацией Gemini:

```dotenv
SCHEMA_VERSION=2
OPENAI_API_KEY=<локальный ключ OpenAI>
GEMINI_API_KEY=<локальный ключ Gemini>
GENERATION_PROVIDER=gemini
GENERATION_MODEL=gemini-3.5-flash-lite
TRANSCRIPTION_PROVIDER=openai
TRANSCRIPTION_MODEL=gpt-transcribe
```

Обратная связка: GENERATION_PROVIDER=openai, GENERATION_MODEL=gpt-5.6-terra,
TRANSCRIPTION_PROVIDER=gemini, TRANSCRIPTION_MODEL=gemini-3.5-flash-lite. Обе связки
проверяются интеграционными тестами через настоящий SDK с mock HTTP и fake Gemini.
Модель задаётся независимо для каждой задачи: модель речи нельзя назначать моделью ответа.

Если provider не задан, сохраняется legacy AI_PROVIDER=gemini. Если model не задан,
для Gemini используется GEMINI_MODEL, для OpenAI — соответствующий default выше.
Пустые строки не означают отсутствующее поле: удалите ненужную настройку или
закомментируйте её. Явные GENERATION_MODEL/TRANSCRIPTION_MODEL имеют приоритет над
выбранной Gemini-моделью Dashboard. Environment переопределяет одноимённые поля .env.

## Каталог и возможности

| Точный ID | Поддерживаемая здесь задача | Вход |
| --- | --- | --- |
| gpt-5.6-terra | Responses, streaming текста | text/plain UTF-8, image/jpeg |
| gpt-transcribe | Финальная транскрипция файла | audio/wav, PCM 16-bit |

Основания для каталога: [GPT-5.6 Terra](https://developers.openai.com/api/docs/models/gpt-5.6-terra),
[GPT-Transcribe](https://developers.openai.com/api/docs/models/gpt-transcribe),
[file transcription](https://developers.openai.com/api/docs/guides/speech-to-text).
Это реализованный subset приложения: gpt-transcribe в API умеет также потоковую
транскрибацию и текстовые подсказки; текущий контракт возвращает финальный текст и
не открывает для него путь текстовой генерации Responses.
Каталог не доказывает доступность модели для конкретного аккаунта и не выводит
модальности из префикса имени. Неизвестные модели отклоняются до SDK.

Локальная консервативная политика генерации: до 20 000 000 байт исходного входа
и до 40 000 000 байт оценки JSON/base64 с инструкциями и историей. Это ограничение
приложения, не лимит токенов API. WAV ограничен 25 000 000 байт; проверяются заголовок,
непустые полные PCM-кадры, разрядность 16-bit и отсутствие сжатия. Фактический буфер
WASAPI продолжает ограничиваться существующим AUDIO_MAX_MIB, а сегменты — VAD.

## Поток данных и жизненный цикл

Фабрика создаёт лёгкую оболочку OpenAIProvider только при запросе. SDK AsyncOpenAI
и HTTP-клиент создаются внутри worker/event loop, не при перечислении реестра.
Каждая попытка владеет своим клиентом; stream закрывается контекстом, SDK закрывает
HTTP-транспорт, резервный finally закрывает его только если он ещё открыт.
Активный SDK не закрывается из Tk-потока.

JPEG передаётся как base64 data URL input_image. Системный промпт/профиль передаётся
через instructions, история — отдельными user/assistant сообщениями. Аудио отправляется
multipart с именем recording.wav и MIME audio/wav; язык явно не фиксируется.
Новые разговоры, записи аудио и снимки на диск не сохраняются.

Responses публикует накопленный текст из response.output_text.delta. Успех требует
response.completed со status=completed и непустым финальным output_text. Финальный
текст сверяется с предварительным. Failed/incomplete/error и конец потока без
подтверждения не считаются успехом. Основание: [streaming events](https://developers.openai.com/api/docs/guides/streaming-responses).

Используются store=False, явная RAM-история и reasoning effort none для текущей
модели. store=False не является обещанием нулевой серверной retention-политики.
Распознанный вопрос по-прежнему редактируется и подтверждается; вся операция имеет
один UUID. ApplicationController, TaskOrchestrator и VAD FIFO не переписывались.

## Ошибки, отмена, безопасность

- SDK retries отключены. До трёх попыток одной модели и одного провайдера допускаются
  для сети, timeout, 408/409, временного 429 и 5xx; backoff 0.25/0.5 секунды ограничен
  общим TASK_TIMEOUT. REQUEST_TIMEOUT ограничивает каждую попытку вместе с чтением stream.
- Ошибки авторизации/прав 401/403, неизвестная модель 404, некорректный запрос,
  исчерпанная квота и пустой/неполный финальный ответ не вызывают бессмысленных повторов.
- При повторе очищается частичный текст. История получает только один успешный итог.
  Автоматического перехода на Gemini или другую OpenAI-модель нет.
- Отмена проверяется до запроса, при публикации и во время ожидания с интервалом до
  50 мс. Pending async task отменяется и ожидается до закрытия stream/client. Registry
  дополнительно отсекает результат после отмены, закрытия и дедлайна.
- OPENAI_API_KEY — SecretStr, исключённый из repr. В диагностику не включаются
  исключения SDK, тела ошибок, изображения, запросы или ответы. Verbose SDK content
  logging отключён. HTTP endpoint закреплён за api.openai.com; OPENAI_BASE_URL и
  неявные organization/project environment-поля не перенаправляют ключ. Redirect
  forwarding отключён; custom endpoints относятся к отдельному этапу.
- Только фабрика Gemini получает Gemini-ключ, только фабрика OpenAI — OpenAI-ключ.
  В смешанной конфигурации аудио получает провайдер транскрибации, а подтверждённый
  текст/историю/профиль или JPEG — явно выбранный провайдер генерации.

## Схема 2

Переход 0/1 → 2 меняет только SCHEMA_VERSION; отсутствие новых полей сохраняет
Gemini defaults. Комментарии, неизвестные ключи, секреты и Markdown-профили сохраняются.
Используется прежняя межпроцессная блокировка, защищённый staging, ReplaceFileW и
восстановление backup. Сохранение legacy-файла проверяет сырые значения независимо от
прямых env-переопределений; явное исправление поля той же транзакцией допускается.
Миграция идемпотентна, будущая/неоднозначная версия запрещает запись.

Версия повышена, чтобы старое приложение Stage 4.1 отказалось читать новую
конфигурацию вместо молчаливого игнорирования OpenAI-привязок и отправки в Gemini.
Откат на старый код требует осознанного восстановления прежней конфигурации при
остановленных процессах; автоматически понижать SCHEMA_VERSION не следует.

## Проверки и ограничения

173 теста на Python 3.10–3.12, включая 28 новых тестов Stage 4.2. Официальный SDK
исполняется на OfflineHTTP транспорте: Responses SSE, multipart WAV, ошибки, отмена,
timeout, освобождение клиентов, обе смешанные связки, 100 последовательных и
12 конкурентных запросов, VAD FIFO, история, restart bindings и миграции.
Команды проверки приведены в README; Windows CI выполняет ту же матрицу. Отдельно на текущей Windows 11 реальная управляемая служба дважды запущена с временным OpenAI-only .env без Gemini-ключа, выполнила миграцию 1 → 2, штатно завершилась по EOF и успешно стартовала повторно. Создание SDK-клиентов в этом smoke было запрещено, запросов к API не было.

Платные live-запросы не выполнялись. Реальные доступ, стоимость, задержка, точность
распознавания русского/английского, сетевые условия и серверные ограничения требуют
отдельного разрешённого live-тестирования. [Аппаратный чек-лист Windows](../audits/STAGE_3_FINAL_AUDIT.md)
остаётся актуальным; mocks не считаются проверкой устройств. Зависший нативный вызов
нельзя безопасно убить Python-потоком; прежний watchdog управляемой службы сохранён.
