# Stage 2.3 — отчёт о проверке и оставшихся работах

## Executive Summary

Проведены две итерации аудита, исправлены сохранение профилей, восстановление Dashboard, установка Windows hook, ошибки аудиоколбэка и обработка временных копий `.env`. Выполнены автоматические и отдельные реальные Windows 11 проверки. Это **промежуточная оценка готовности**: физическая клавиатура, отключение аудиоустройства, многомониторные конфигурации и Windows 10 ещё требуют проверки.

База `d5be0b0`, чистая рабочая директория. На Windows исходные 57 тестов прошли на Python 3.10.22, 3.11.18 и 3.12.10. Ruff и проверка форматирования прошли на 3.12. Карта и воспроизводимые проблемы — в [реестре аудита](STAGE_2_3_AUDIT.md).

## Исправления

- Сохранение профиля через временный файл и атомарную замену; при ошибке исходный файл сохраняется.
- Откат переключателей и селекторов при неуспешной записи настроек; выбор профиля применяется только после успешного сохранения.
- Настройки, переопределённые окружением, больше не сохраняются с вводящим в заблуждение отображением.
- Ошибка фонового перечисления устройств передаётся в GUI без раскрытия содержимого исключения.
- Добавлены регрессионные тесты, в том числе 100 последовательных задач с подставной моделью, и CI для трёх версий Python на Windows.
- Установка клавиатурного hook подтверждается получением Win32 handle до применения настроек. Для pointer-width возвращаемых значений настроены типы ctypes; pynput закреплён на протестированной версии 1.8.2 из-за использования внутреннего интерфейса.
- Ошибка PortAudio callback передаётся основному потоку с освобождением ресурсов. Проверены 30 циклов запуска/отмены VAD и ограничение FIFO на 10 000 сегментов с подставными данными.
- Временные файлы настроек получают отдельный игнорируемый Git префикс; при обычных ошибках записи удаляются.

## Security Findings

- `pip-audit -r requirements.txt`: известных уязвимостей в разрешённом на момент проверки наборе не найдено. Зависимости не закреплены lock-файлом, поэтому будущая разрешённая версия может отличаться.
- `bandit -q -r config core ui main.py`: два предупреждения Low (B404, B603) о `subprocess`. Проверенный вызов запускает `sys.executable` и фиксированный `main.py` списком аргументов без shell; пользовательский ввод в команду не подставляется. Предупреждения не подавлялись.
- Поиск по истории Git для ограниченных шаблонов Google API key, GitHub token и заголовков приватных ключей не нашёл совпадений. Это не полноценная проверка всех возможных типов секретов.
- `.env` и пользовательские профили исключены из Git. Ключ хранится в `.env`, а не в системном хранилище секретов. Экран, аудио, инструкции и история, необходимые для инициированных действий, отправляются Gemini; локальная история находится в RAM.
- Named mutex/event используют `Local\\` и имя с хешем пользователя; это механизм координации, а не аутентифицированный IPC. Политика ACL и сценарии с несколькими пользователями требуют отдельной проверки на целевой системе.
- IPC управляемой службы использует унаследованный stdin pipe, а не публичный сетевой порт. Доступ к локальной сессии и отдельному процессу следует считать границей доверия; именованное событие активации может влиять на показ Dashboard.
- Временные файлы хранятся рядом с целевыми для атомарной замены и наследуют права каталога. На Windows индивидуальные ACL исходного `.env` при замене не гарантированно сохраняются; права каталога и созданного файла нужно проверить. Исключение из Git не шифрует временный файл после аварии.

## Testing Results

```powershell
python -m unittest discover -s tests -q
python -m compileall -q config core ui tests main.py
python -m ruff check config core ui tests main.py
python -m ruff format --check config core ui tests main.py
python -m pip_audit -r requirements.txt
python -m bandit -q -r config core ui main.py
```

Локально прошли 73 теста на Python 3.10.22, 3.11.18 и 3.12.10, а также Ruff и compileall. По сообщению пользователя, предыдущий Windows CI успешно выполнился на Python 3.10, 3.11 и 3.12. Результат GitHub Actions для новых коммитов не подтверждён. Bandit возвращает ненулевой код из-за перечисленных предупреждений.

## Windows Verification

На Windows 11 выполнены реальные установка/снятие клавиатурного hook и WASAPI/VAD-захват, тест Windows mutex, а также указанные циклы Dashboard и службы. ## Known Limitations

- Глобальный ввод не блокирует сочетания в других приложениях; конфликты с внешними программами не всегда обнаруживаются.
- Слушатель использует закрытые внутренние интерфейсы зафиксированной версии pynput; физические клавиши, раскладки и фокус нужно проверить вручную. Внешние приложения всё ещё могут перехватывать комбинацию.
- Не проведены длительная проверка аудио и стресс-тест реальной смены профилей/хоткеев; короткий тест аудио оставил дополнительные потоки в процессе измерения.
- Не проверены реальные Gemini-квоты, сетевые обрывы и поведение конкретных моделей с реальным проектом API.
- Резервное копирование файлов и безопасное системное хранилище ключей не реализованы.
