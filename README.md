# 👻 GhostAssist

GhostAssist — Windows-приложение для разбора вопросов с экрана и из системного звука через Gemini. Dashboard управляет службой, моделью, горячими клавишами и Markdown-профилями. Ответ выводится в плавающем HUD.

- Полноэкранный захват снимает основной монитор и уменьшает JPEG до заданных размеров с сохранением пропорций.
- Выделение снимает прямоугольник виртуального рабочего стола в исходном разрешении. Области более 40 млн пикселей отклоняются.
- Запись WASAPI использует выбранный loopback или устройство вывода по умолчанию. Аудио упаковывается в WAV в памяти.
- Записанная речь отправляется в Gemini для транскрибации. Распознанный текст можно проверить и исправить перед запросом ответа.
- Режим **TEST** запрашивает краткий ответ на вопрос с экрана. **INTERVIEW** включает выбранный профиль в системную инструкцию. Для звука используется инструкция INTERVIEW.
- Снимок или аудио отправляется в Gemini. Текст активной попытки показывается по мере поступления.

## Установка

Поддерживаемые версии — Windows 10/11, Python 3.10–3.12 с Tk. Для запросов нужны ключ Gemini API, интернет и доступ к Gemini для вашей учётной записи.

```powershell
git clone https://github.com/max1maln0/GhostAssist.git
cd GhostAssist
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m ui.dashboard
```

Введите ключ в поле Dashboard, нажмите **Сохранить ключ**, затем **Запустить службу**. Dashboard открывается и без ключа. Для настройки вручную скопируйте `.env.example` в `.env` и заполните `GEMINI_API_KEY`. Ключ хранится локально в `.env`. Переменные окружения имеют приоритет над файлом.

Консольный запуск службы — `python main.py`. Конфигурация и профили ищутся относительно каталога проекта. Изменения параметров службы через Dashboard применяются перезапуском службы. Горячая клавиша Dashboard и поведение кнопки X применяются сразу. После ручного редактирования `.env` перезапустите соответствующий процесс.

## Фоновый режим

Нажмите «Скрыть в трей», чтобы убрать Dashboard с рабочего стола. Служба, VAD, очередь и история текущего процесса продолжают работать. Откройте Dashboard через значок GhostAssist в области уведомлений или нажмите `Ctrl + Shift + F9`. В меню значка доступны открытие и скрытие Dashboard, запуск и остановка управляемой службы, отмена задачи и завершение приложения.

По умолчанию кнопка X скрывает Dashboard. Переключатель «Закрывать в трей» меняет это поведение и сохраняет его в `CLOSE_TO_TRAY`. Для полного завершения выберите «Завершить GhostAssist» в трее или Dashboard. Служба получит команду завершения и закроет активные задачи и аудиозахват. Если процесс не отвечает в течение четырёх секунд, Dashboard завершит его принудительно.

Windows Named Mutex ограничивает количество экземпляров Dashboard и службы по отдельности для текущего пользователя и Windows-сеанса. Повторный запуск Dashboard посылает сигнал уже запущенному экземпляру. При аварийном завершении Windows освобождает дескриптор. Если служба запущена отдельно через `main.py`, Dashboard покажет этот статус. Завершите отдельную службу перед запуском управляемой службы.

Значок трея может быть скрыт Windows в меню дополнительных значков. Пока значок ещё не создан, Dashboard остаётся видимым. Для полного завершения в этом случае доступна кнопка в Dashboard.

Dashboard принимает сочетания с модификаторами и одиночные служебные клавиши, например F1–F12. В окне выделения Esc отменяет выделение. Прямоугольник должен быть больше 15 × 15 пикселей.

## Настройки и обработка ошибок

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `CLOSE_TO_TRAY` | `true` | Скрывать Dashboard по кнопке X |
| `GEMINI_MODEL` | `gemini-3.5-flash-lite` | Первая модель в очереди |
| `ACTIVE_PROFILE` | `example_legend.md` | Имя Markdown-файла из `config/profiles/` |
| `CROP_WIDTH` / `CROP_HEIGHT` | 1280 / 720 | Верхняя граница размеров полноэкранного снимка |
| `REQUEST_TIMEOUT` | 12 с | Дедлайн одной попытки Gemini, от 0,1 до 60 с |
| `TASK_TIMEOUT` | 30 с | Общий бюджет обработки, от 0,1 до 120 с |
| `AUDIO_MAX_SECONDS` | 60 с | Максимальная длительность захвата, от 1 до 60 с |
| `AUDIO_MAX_MIB` | 12 МиБ | Верхняя граница PCM-буфера, от 1 до 12 МиБ |

После второго нажатия аудиоклавиши или достижения лимита ручная запись останавливается и начинается транскрибация. Предел PCM не включает копии при формировании WAV и сериализации запроса. Пустая запись или отключение устройства приводят к сообщению в HUD. Следующая запись заново определяет устройство вывода.

Обработка экрана и звука выполняется по одной задаче, VAD-захват работает параллельно. Во время записи аудиоклавиша завершает запись. Во время обработки команды нового захвата игнорируются. Отмена закрывает окно выделения или сигнализирует фоновому исполнителю завершить захват либо сетевой поток. Приложение отбрасывает запоздавший вывод и принимает следующую задачу после освобождения исполнителя. Gemini может продолжать серверную обработку уже принятого запроса.

При временном сетевом сбое, квоте, недоступности модели или неполном ответе приложение пробует следующую модель с короткой паузой в пределах общего бюджета. После выбранной модели очередь включает `gemini-3.5-flash-lite`, `gemini-3.1-flash-lite` и `gemini-3.6-flash` без повторов. Ошибки ключа и доступа завершают запрос сразу. Доступность зависит от проекта Gemini. [Каталог моделей Gemini](https://ai.google.dev/gemini-api/docs/models)

HUD и рамка выделения запрашивают ограничение захвата через Win32 `SetWindowDisplayAffinity`. Поддержка зависит от версии Windows и способа захвата. Проверьте поведение с используемым приложением записи или демонстрации экрана. [Документация Win32](https://learn.microsoft.com/windows/win32/api/winuser/nf-winuser-setwindowdisplayaffinity)

## Аудио и VAD

В Dashboard выберите устройство WASAPI Loopback и при необходимости обновите список. Пустой `AUDIO_DEVICE` означает устройство по умолчанию. Выбор сохраняется по имени. Если устройство отключено или имена совпадают, появится ошибка. Можно выбрать устройство по умолчанию.

Ручная запись запускается и останавливается `Alt + R` или Mouse 5. После транскрибации откроется окно редактирования. Проверьте текст и нажмите «Отправить», либо отмените задачу. Параметр `AUTO_SEND_TRANSCRIPT` включает автоматическую отправку и по умолчанию выключен. Аудио передаётся в Gemini, доступ и тариф зависят от используемого API.

Переключатель «VAD при записи» выбирает режим обнаружения речи. После его включения запись всё равно нужно явно запустить клавишей аудио. HUD показывает активную запись. Получите согласие участников разговора в соответствии с применимыми правилами. Остановка мониторинга выполняется клавишей отмены или повторным нажатием клавиши аудио. Захват продолжается во время транскрибации, проверки и генерации. Сегменты обрабатываются по очереди, одновременно открывается одно окно проверки. В очереди хранится до четырёх сегментов, а суммарный размер WAV в очереди ограничен четырьмя пятыми `AUDIO_MAX_MIB`. PCM одного сегмента ограничен меньшим из `VAD_MAX_SECONDS` и одной пятой `AUDIO_MAX_MIB`. Это ограничение не включает временные копии WAV и данные сетевого запроса. При переполнении новые сегменты отклоняются, а HUD показывает количество пропущенных сегментов. Глобальная клавиша отмены останавливает мониторинг, отменяет активную обработку и очищает очередь. Кнопка «Отменить» в окне проверки отклоняет текущую реплику, оставляя мониторинг и очередь активными.

WebRTC VAD использует моно PCM 16 кГц. Он отсеивает короткие импульсы и обнаруживает паузу, но музыка и шум могут ошибочно распознаваться как речь. Доступны `VAD_MIN_SPEECH_MS`, `VAD_SILENCE_MS`, `VAD_MAX_SECONDS` и `VAD_SENSITIVITY`. Значения по умолчанию — 300 мс, 900 мс, 30 секунд и уровень 2 соответственно. Длительность сегмента ограничена также размером аудиобуфера. Индикаторы времени, размера данных и номера попытки выводятся без текста разговора и ключа.

### Выбор обработки речи

| Вариант | Ресурсы и назначение |
| --- | --- |
| Gemini Audio | Транскрибация через уже используемый API. Не требует загрузки локальной модели, но зависит от сети и тарифа. |
| Локальное распознавание Whisper | Позволяет выполнять распознавание локально. Скорость и память зависят от размера модели и устройства. Для этой версии потребуется дополнительно распространять модель. |
| WebRTC VAD | Компактный классификатор коротких PCM-кадров. Используется в проекте без отдельной нейросетевой модели и сетевого запроса. |
| Silero VAD | Нейросетевой детектор с ONNX/PyTorch. Требует модель и runtime. Его качество и задержку для данного проекта ещё предстоит измерить. |

Сравнение служит выбору реализации. Замеры точности русского и английского языка и сравнительное тестирование VAD на музыке в этом проекте ещё не проводились. [Gemini Audio](https://ai.google.dev/gemini-api/docs/audio) · [WebRTC VAD](https://github.com/wiseman/py-webrtcvad) · [Silero VAD](https://github.com/snakers4/silero-vad)

## Память диалога

Dashboard показывает количество завершённых взаимодействий по режимам, позволяет включить память и выбрать глубину от 1 до 10. История хранится в RAM, отдельно для TEST и INTERVIEW. Очистка перезапускает службу и отменяет текущую задачу. Перезапуск службы также начинает новую сессию. Для экранных запросов в историю сохраняются полные ответы в формате «Вопрос: … Ответ: …». Для аудио используется проверенная транскрипция. Отменённые ответы пропускаются. Параметры в .env — `MEMORY_ENABLED` и `MEMORY_DEPTH`.

## Структура

| Компонент | Роль |
| --- | --- |
| `main.py`, `core/task_state.py` | Хоткеи, очередь команд Tk, состояния задач и завершение |
| `core/audio_worker.py` | Захват WASAPI и сборка WAV |
| `core/llm_worker.py` | MSS/JPEG, поток Gemini, резервные модели и тайм-ауты |
| `core/context_manager.py` | Режимы и инструкции с профилем |
| `config/settings.py`, `config/env_file.py` | Загрузка, проверка и сохранение настроек |
| `ui/dashboard.py`, `ui/tray.py` | Настройки, трей и управление дочерним процессом |
| `core/single_instance.py` | Ограничение экземпляров и сигнал восстановления Dashboard |
| `ui/snipping_tool.py`, `ui/stealth_hud.py` | Выделение и вывод на главном потоке Tk |

## Проверки

```powershell
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
python -m compileall -q config core ui tests main.py
python -m ruff check config core ui tests main.py
python -m ruff format --check config core ui tests main.py
```

Тесты используют подставные ответы Gemini и аудиоустройство. Для ручной проверки на Windows используйте реальное устройство вывода, попробуйте запись и отмену во время генерации. Проверьте выделение на нескольких мониторах с разным DPI, включая монитор слева или выше основного, и поведение HUD в используемом ПО захвата.

## Roadmap

Stage 1 стабилизирует существующие сценарии захвата, запросов и настройки. Stage 2 добавляет память диалога, транскрибацию, VAD и выбор loopback-устройства. Возможные следующие этапы — постоянное хранение сессий по желанию пользователя и отдельные реализации захвата для macOS и Linux.
