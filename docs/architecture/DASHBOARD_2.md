Мониторинг речи начинается только явным действием пользователя. Новый Dashboard не запускает VAD автоматически. Очередь, UUID задач, отмена и история обслуживаются прежними ApplicationController/TaskOrchestrator.

## Слои интерфейса

- `ui/dashboard.py`: композиция окна, навигация, общие состояния, адаптивная нижняя панель.
- `ui/dashboard_pages/`: создание виджетов семи страниц.
- `ui/dashboard_components.py`, `dashboard_theme.py`: карточки, поля, тема, корректный перенос строк и прокрутка.
- `dashboard_actions.py`, `dashboard_profiles.py`, `dashboard_hotkeys.py`, `dashboard_service.py`: действия соответствующих областей.
- `dashboard_settings.py`: временный patch-черновик над Settings и один транзакционный путь сохранения.
- `dashboard_jobs.py`: по одному ленивому worker на запись/hook, доступ к API и WASAPI scan. В каждой очереди помещается одна операция/результат. Повторный запуск занятого канала отклоняется.

Виджеты обновляет главный поток через poll. Фоновые функции не вызывают Tk. Закрытый JobRunner игнорирует поздний результат и освобождает подготовленный listener. Зависший нативный scan нельзя принудительно прервать потоком; он остаётся единственным daemon-worker своего канала, повторные scan не плодят потоки.

CTk 5.2.2 вызывает update_idletasks внутри scrollbar.set. ScrollbarBridge объединяет значения и рисует их по одному таймеру 16 мс, вне синхронного layout callback. Это предотвращает обнаруженную рекурсивную прокрутку на Windows CI. При уничтожении окна новые таймеры не планируются, старые отменяются. Перенос текста рассчитывается по ширине внешнего frame с учётом scaling, а не по ширине дочерней текстовой метки.

## Черновик, файл и запущенная служба

Изменения обычных полей не записывают файл сразу. «Сохранить» валидирует patch, перечитывает актуальные настройки под существующим configuration_lock и вызывает update_env. Другие поля, комментарии и индивидуальный DACL сохраняются. Если то же поле изменено другим процессом, требуется обновить форму через отмену правок. Переопределённое environment поле нельзя незаметно записать как якобы применённое значение.

Ошибка записи оставляет сохранённую конфигурацию и черновик; подготовленный hook закрывается. Клавиша Dashboard устанавливается до записи и заменяет прежний listener только после успешного commit файла. Сервисные сочетания проходят пробную установку hook, а работающая служба получает их после явного перезапуска. До установки своего hook Dashboard проверяет конфликты с известной фактической конфигурацией службы. При внешней/ещё не подтверждённой службе переназначение ограничено.

Служба подтверждает READY только после установки своих hooks. Передаются generation/transcription, VAD и SHA-256 сигнатура фактического snapshot, без исходных значений секретов. Сигнатура служит локальным сравнением и не является механизмом авторизации. STATE передаёт режим, HUD и активность записи; SESSION — только два счётчика; ERROR — фиксированный безопасный код. В UI не выводится произвольный stdout или тело ошибки провайдера. Строки ограничены 8192 байтами, очередь — 32 элементами, источник привязан к конкретному Popen.

«Применить и перезапустить» отменяет работу и останавливает только дочернюю службу текущего Dashboard. EOF запускает штатное завершение; watchdog через 4 секунды может завершить собственный неотвечающий процесс. Внешняя служба не убивается и её привязки/история не объявляются известными. Сохранение само по себе не перезапускает процесс. Перезапуск очищает обе истории в RAM.

Кнопки HUD и переключения режима используют stdin H/D/M, отмена — C; служба ставит действия в существующую очередь Tk, без обновлений из reader thread.

## Ключи и проверка доступа

Поля ключей всегда изначально пусты и маскированы. Сохранение/замена отдельны для двух провайдеров. Удаление подтверждается и останавливает собственную службу, использующую ключ, чтобы он не оставался в её памяти. Environment override удалением файла не снимается: такая операция отклоняется с объяснением.

GET модели выполняется только по нажатию пользователя. Адреса закреплены за официальными API, redirects выключены, общий budget 5 секунд, тело метаданных ограничено 64 КиБ. Gemini использует x-goog-api-key, OpenAI — Authorization; ключ не включается в URL. Профили, история, скриншоты и WAV не передаются. Проверка различает отсутствие ключа, авторизацию/права, отсутствие модели, тайм-аут и общую ошибку. Ответ с другим ID не считается успешным. Проверка не доказывает наличие квоты, качество ответа или доступность генерации.

Источники протокола: [OpenAI retrieve model](https://developers.openai.com/api/reference/python/resources/models/methods/retrieve), [Gemini models.get](https://ai.google.dev/api/models). Каталог модальностей остаётся локальным и консервативным; новые модели автоматически не добавляются.

## Проверки

```powershell
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
python -m ruff check config core platform_adapters providers ui tests main.py
python -m ruff format --check config core platform_adapters providers ui tests main.py
python -m compileall -q config core platform_adapters providers ui tests main.py
```

Повторять на Python 3.10, 3.11, 3.12. Unit-тесты используют HTTPX MockTransport, fake WASAPI и провайдеры, временные .env и профили. GUI-тесты создают настоящий CustomTkinter Dashboard с отключёнными рабочими интеграциями; если графический Tk недоступен, это явно отмечается skip. Они проверяют навигацию, транзакции формы, ключи, профили, устройства, capture, отмену правок, масштабы и границы кнопок. Зависший GUI-тест имеет fail-fast watchdog 90 секунд, job CI — 15 минут.

На локальном Windows 11 выполнен реальный визуальный проход семи страниц и сохранены семь снимков без ключей/разговоров. Они остаются локальными QA-артефактами вне Git. Проверялись карточки, отступы, навигация и прокрутка; найденный перенос длинного заголовка исправлен. Программные масштабы CustomTkinter 1.0/1.25/1.5 и узкое окно проверяются GUI-тестами. Это не равнозначно ручному изменению системного DPI Windows на нескольких мониторах.

## Оставшийся ручной чек-лист

1. Windows 10 и Windows 11: системный масштаб 100/125/150%, окно около 1100×750 и минимальное; пройти все страницы, прокрутить до конца, проверить меню/подсказки и нижние кнопки. Отдельно проверить перенос окна между мониторами с разным DPI.
2. На своих ключах явно выполнить metadata check обоих провайдеров; затем отдельно разрешить реальный платный запрос. Проверить экран, область, ручное аудио, review/редактирование, streaming и отмену. Такие API-запросы при разработке не выполнялись.
3. На реальном WASAPI-устройстве включить VAD, воспроизвести несколько реплик, отключить USB/HDMI во время записи, проверить сообщение, завершение FIFO и новый запуск. Физическое отключение и длительный VAD не проверялись этим GUI-этапом.
4. Запустить службу, сохранить другую модель/профиль: старый процесс должен продолжать работу до явного применения. После перезапуска проверить READY, пустую историю, новые привязки и освобождение устройств.
5. Проверить системный трей: скрытие/восстановление, × при двух сохранённых значениях, меню stop/cancel/exit и второй Dashboard. Отдельно запустить внешнюю main.py: Dashboard должен только показать её наличие.
6. Принудительно завершить собственную службу в диспетчере задач: Dashboard должен показать сбой и разрешить повторный запуск. Проверить штатный выход с активным запросом и watchdog зависшего нативного вызова.

Постоянное хранение истории, новые провайдеры, автозапуск и настройки несуществующих функций не добавлялись.
